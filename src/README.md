# Экспериментальный анализ алгоритмов сортировки

**Цель практики:** Изучить поведение различных алгоритмов сортировки на практике, освоить методологию бенчмаркинга (измерения времени работы программ), научиться анализировать вычислительную сложность алгоритмов в зависимости от структуры входных данных и грамотно оформить результаты.

### Базовые алгоритмы:

$O(n ^ 2)$
- Bubble Sort
- Selection Sort
- Insertion Sort

$O(n \log n)$
- Quick Sort
- Merge Sort
- Heap Sort

$O(n)$
- Counting Sort
- Radix Sort
- Bucket Sort

$Встроенные$
- `sorted()` / `.sort()` (Python)

##  Результаты экспериментальных замеров (Полный набор данных)


 * Из-за отсутствия поддержки библиотеки tracemalloc и особенностей работы JIT-компилятора в PyPy, подсчет расхода памяти был реализован через перехват TypeError при вызове `sys.getsizeof()` с расчетом базового размера итогового списка (len × 8 байт).

**Анализ результатов и особенности реализации**

* **Встроенная сортировка (`Built-in`):** Показывает наивысшую скорость во всех тестах благодаря оптимизациям на Си в CPython и эффективному JIT-компилированию в PyPy. На частично и полностью отсортированных данных демонстрация алгоритмом времени $O(N)$ делает его безусловным лидером.
* **Простые алгоритмы  - Bubble, Selection, Insertion:** Проявляют сильную квадратичную зависимость. На выборках с $N \ge 100000$ выполнение обрывается из-за превышения временного лимита. При этом `Insertion Sort` на упорядоченных массивах работает за $O(N)$, опережая большинство сложных алгоритмов.
* **Эффективные алгоритмы  - Quick, Merge, Heap:** Показывают стабильный масштаб на больших наборах ($N = 10000000$). В CPython `Quick Sort` опережает `Merge Sort` и `Heap Sort`.
* **Несравнивающие сортировки - Counting, Radix, Bucket:** Демонстрируют высокое быстродействие на случайных данных, однако `Bucket Sort` резко замедляется при $N = 10^6$ в CPython из-за издержек на распределение и создание списков/бакетов в чистом Python.
* **Влияние интерпретатора (CPython vs PyPy):** JIT-компилятор PyPy снижает время выполнения чистых интерпретируемых алгоритмов на 1–2 порядка (до 50–100 раз ускорения).

| **Built-in (Timsort)** | ~0.2 сек | ~0.2 сек | Высокооптимизированная гибридная реализация на C. Демонстрирует наивысшую производительность; на упорядоченных массивах достигает линейной сложности $O(N)$. |
| **Quick Sort** | ~1.9 сек | ~0.4 сек | Высокая эффективная скорость на случайных данных. Использование случайного опорного элемента (pivot) нивелирует риск перехода к худшему случаю $O(N^2)$. |
| **Merge Sort** | ~25 сек | ~0.6 сек | Характеризуется алгоритмической стабильностью и сложностью $O(N \log N)$, однако требует выделения дополнительной памяти $O(N)$ и дополнительного времени на копирование элементов. |
| **Heap Sort** | ~31 сек | ~0.9 сек | Выполняет сортировку «на месте» без дополнительной памяти, но уступает Quick Sort по времени из-за нелокальности обращений к кэш-памяти при работе с кучей. |
| **Counting Sort** | ~0.45 сек | ~0.03 сек | Несравнивающая сортировка с линейной сложностью $O(N + K)$. Покажет максимальную скорость при условии относительно небольшого диапазона значений $K$. |
| **Radix Sort** | ~3.5 сек | ~0.35 сек | Поразрядная сортировка с фиксированным числом проходов. Время выполнения не зависит от начальной упорядоченности элементов входного массива. |
| **Bucket Sort** | ~240 сек | ~0.4 сек | В CPython показывает деградацию производительности из-за накладных расходов на динамическое создание и обход списка бакетов; в PyPy масштабируется эффективнее благодаря JIT-компиляции. |
| **Bubble / Selection / Insertion** | Превышение лимита ($N > 10^3$) | Превышение лимита ($N > 10^3$) | Квадратичная сложность $O(N^2)$ делает алгоритмы неприменимыми для массивов $N \ge 10^4$. Исключение — Insertion Sort, работающая за $O(N)$ на почти отсортированных данных. |

**Ограничения и неразрешенные проблемы**

* Алгоритмы со сложностью $O(N^2)$ (Bubble, Selection, Insertion) были принудительно остановлены на размерах $N > 10^3$ во избежание зависания бенчмарка.
* При тестировании `Quick Sort` на наихудших сценариях без случайного выбора опорного элемента происходило превышение лимита рекурсии (`RecursionError`). Проблема была частично решена увеличением `sys.setrecursionlimit()` и переходом на итеративную версию/случайный выбор pivot.
* В CPython создание большого количества вложенных списков на $N = 10^6$ вызвало аномальный рост затрат времени на сборку мусора и работу со ссылками, что не удалось полностью устранить без оптимизации структуры данных на уровне C-расширений.
